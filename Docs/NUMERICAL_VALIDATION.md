## Levels 2–4 — tiny Llama vs float64 Hugging Face

Bound 2e-5 on logits (O(1)); observed max |Δ| 0.8e-6 – 1.3e-6 for all four variants (GQA/untied, MHA/tied × HF split-half RoPE / GGUF-permuted interleaved RoPE). The permuted variants confirm the interleaved-RoPE assumption for GGUF weights. Argmax agrees at every position. Incremental (token-by-token) decode and a 4+3 split prefill equal the single-pass forward **exactly** (0.0) on CPU; bound 5e-6. Cache bounds, reset, failed-forward-doesn't-advance, and weight-shape validation are tested.

### Where each error comes from

- **CPU vs reference (≤ 7e-5 for F16/Q8_0)**: float32 summation order only.
- **Q4_0 CPU 1.6e-3**: the Q4_0 file contains three `Q4_1` tensors (`blk.{0,1,10}.ffn_down`), which alpaca expands to F16 at load; rounding to F16 (relative 2⁻¹¹ per weight) is the difference. This is a loading decision, reported in `LoadReport.notes`, not an arithmetic bug.
- **Metal F16 KV cache (~6e-3)**: isolated experimentally. (1) Layer-wise test (`LayerwiseTests`) runs every GPU stage of every layer on the *CPU's* exact input: rmsnorm 6e-7, linear layers ≈ 3e-7, RoPE 5e-7, SiLU·mul 2e-7 relative to tensor peak — arithmetic is correct — while attention reads 1.0e-3, the f16 K/V rounding. (2) Switching the GPU cache to float32 drops the end-to-end error to 2.9e-5, and the f16-vs-f32 KV difference on the same GPU is 5.7e-3. So the f16 KV cache is a deliberate memory/bandwidth trade costing ~3e-4 of peak logit magnitude on this model, and sits above the noise of any stage. Residual activations reach |x| ≈ 4.4e3 in layer 29, which amplifies absolute errors. Selectable with `LoadOptions.kvPrecision`.
- An earlier hypothesis — that a CPU cache rounded through f16 would match the GPU — failed (still ~4e-3): GPU and CPU `sin/cos` differ by ~1e-7, which flips f16 rounding of some cached values, and 30 layers of attention amplify those flips. Documented here rather than hidden by loosening the bound.

## Phase 3 additions (performance work): what changed numerically and how it was bounded

Defaults are now `GEMMPrecision.fast` (prefill projections on the matrix hardware) and `KVPrecision.float16`; `.exact` / `.float32` are one option away and are the configurations the 5e-4 GPU-vs-CPU test uses. Each reduced-precision element is isolated by its own test.

| component | what is rounded | test and bound | observed |
|---|---|---|---|
| Tensor-op GEMM (`.fast`), batches ≥ 16 | activations → half, weights → half (quantised weights: `d·q` rounded to half), float32 accumulate | per-element analytic bound `2⁻¹⁰·Σ|xₖwₖ|` (+1e-5), K ∈ {64…1536}, N not a multiple of 64, T ∈ {32…300}, f16/q8_0/q4_0 (`FastGEMMTests`) | worst error = **31%** of the bound |
| Fused residual (`C += A·B`) | same | `linearAdd` vs CPU for T ∈ {1…100}: exact 2e-4, fast 2e-2 absolute (values ≤ ~20) | exact ≤ 1e-5; fast ≤ 4.4e-3 |
| Fused gate+up+SiLU | same, through SiLU and a product | peak-relative 3e-3 | ≤ 8.3e-4 |
| Tiled attention (T ≥ 8) | Q, softmax weights P, K, V → half | vs float64-accurate CPU reference on the same half K/V: ≤ 1.5e-3 (3·2⁻¹¹·max|V|), 10 shapes incl. partial tiles, GQA 1–4, hd 64/128, chunk offsets | **≤ 2.0e-4** |
| Split-K decode attention (T = 1) | K/V half (same as before); float32 elsewhere | 13 context lengths around split boundaries, GQA 1–8, hd 64/128: 2e-6 | **≤ 1.2e-7** |
| Fused decode mat-vecs, RoPE+KV store, GPU arg-max | float32 reorderings only | covered by the 5e-4 GPU-vs-CPU test (exact config) and by 40-step token-for-token equality of the chained GPU greedy path with the synchronous path | 2.7e-5; tokens identical |

**Real model, default GPU configuration vs Hugging Face float32 on the same weights** (last-token logits, peak-relative = max|Δ| / max|logit|; bound 3e-3):

| file | 5 tokens | 16 tokens | 90 tokens |
|---|---|---|---|
| F16  | 6.2e-3 abs / 3.0e-4 | 1.8e-2 / 5.3e-4 | 2.1e-2 / 1.3e-3 |
| Q8_0 | 1.4e-2 / 6.7e-4 | 3.5e-2 / 1.0e-3 | 1.3e-2 / 8.5e-4 |
| Q4_0 | 9.4e-3 / 5.2e-4 | 1.6e-2 / 4.8e-4 | 2.2e-2 / 1.5e-3 |

Greedy continuations: **72/72 tokens identical** to the reference on the GPU for all three files (synchronous decoding in `MetalRealModelTests`). The chained GPU-arg-max path is checked token-for-token against that synchronous path over 40 steps (`testGPUGreedyChainMatchesSynchronousDecoding`, including early stop and capacity limits) and against the reference through the public API (24 tokens, `PublicAPITests`). Isolating the contributions on the 90-token prompt: `.fast` vs `.exact` GEMM 1.1–1.4e-3 (peak-relative), f16 vs f32 KV cache 4.7e-4 (7.2e-3 abs), exact config vs CPU **2.7e-5**. The earlier absolute bound (5e-2) was replaced by a peak-relative one because every reduced-precision element scales with logit magnitude.

Not weakened: all Phase 1–2 bounds (CPU 5e-4 / 7e-4 / 1.6e-2, kernels vs CPU, tiny-model 2e-5) are unchanged and still pass. The GPU-vs-CPU test now selects the exact configuration explicitly instead of inheriting a faster default.

Known limitation: the chained greedy path treats NaN logits as "never the maximum" and returns token 0 if every logit is NaN, where the CPU sampler throws. A model producing NaN logits is already broken; this is flagged, not handled.

## Tokenizer

191/191 corpus entries match reference token IDs: English, punctuation, contractions, whitespace (leading/trailing/runs/tabs/CRLF/newlines), numbers incl. Unicode numerics (², ½, ٣, Ⅷ), CJK, Arabic, Cyrillic, Korean, Hindi, emoji (ZWJ sequences, flags), special tokens (also partial `<|im_start`), empty string, 200-char runs, NUL/zero-width/combining characters, and 150 seeded random strings. Decode round-trips; streaming decode never emits partial UTF-8.

## Robustness tests

GGUF: bad magic/version/endianness, **every truncation prefix**, huge counts and lengths (u64 max), array length beyond file, duplicate keys/tensors, zero/overflowing dimensions, unknown tensor type, misaligned/out-of-range/overlapping offsets, and 20,000 seeded byte-mutation/insert/truncate fuzz cases (≈ 9% parse — all tensor ranges then verified in bounds; the rest rejected with `GGUFError`; no traps). API: corrupt/truncated/missing model files, empty prompt, invalid parameters, context exhaustion, memory-budget refusal, cancellation mid-generation (explicit and via `Task` cancellation), repeated load/unload (resident size flat at 77–78 MiB over 6 cycles), concurrent isolated sessions equal their solo runs, unload during generation.

## Not covered

Allocation-failure injection for GPU buffers; real iOS hardware; models other than SmolLM2-135M; ASAN/TSAN runs; long-context (≥ 4k) accuracy; bf16 safetensors vs GGUF-F16 logit gap (`hf_original` references are generated but no test asserts on them yet).
